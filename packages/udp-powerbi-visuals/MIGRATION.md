# Moving udp-powerbi-visuals into the UDP monorepo

How this package becomes part of UDP once approved. It was laid out from the UDP monorepo's own
conventions (`udp-monorepo-development`: `.claude/CLAUDE.md`, `packages/udp-stencil-component-library/stencil.config.ts`,
`packages/udp-react-enterprise-component-library/docs/{standards,design-tokens,charts/guidance}.md`),
so the move is mostly a copy. Nothing here changes the UDP repository until that green light.

## What moves, and what stays in PowerReact

| Piece | Destination |
| :--- | :--- |
| `src/components/{kpi,charts,tables}/udp-pbi-*` (tsx, css, readme) | `udp-stencil-component-library/src/components/powerbi-visuals/…` |
| `src/functional`, `src/utils`, `src/styles` (internal) | `udp-stencil-component-library/src/components/powerbi-visuals/{functional,utils,styles}` |
| React wrappers | Generated by UDP's React output target into `udp-react-stencil-component-library`; one thin wrapper per element in the enterprise library (below) |
| Manifest engine (`src/lib/manifest`), filter store, BFF, the slicer control | Stay in PowerReact for now. In UDP they become a page or a dashboard widget of the enterprise library, a separate decision. The slicer maps to `UdpDropdown` (multiselect) or `UdpTablist`. |

## Steps

1. **Copy** the folders above. Keep the tags (`udp-pbi-*`) and classes (`UdpPbi*`): they already
   follow UDP naming. `styleUrls` paths are relative and keep working.
2. **Dependencies** in `udp-stencil-component-library/package.json`: `d3-scale`, `d3-shape`,
   `d3-array` (quantiles, extents), `d3-hierarchy` (treemap) and `d3-time` (calendar weeks), with their
   `@types/*`. All are small ES modules with no DOM access, safe in Stencil's hydrate build. Icons use `lucide`. Either add it, or swap the few icons in
   `src/utils/icons.ts` for the UDP icon registry (`src/icons/icon-registry.json`). The CSV / XLSX
   export uses SheetJS through a dynamic import, calling only `utils.aoa_to_sheet`, `utils.book_new`,
   `utils.book_append_sheet` and `write`; all four exist in the `xlsx` 0.18.5 UDP already ships.
3. **Stencil**: UDP pins 4.41.x; this package builds with 4.45.x and uses no API newer than 4.41
   (Shadow DOM, `@Prop` / `@State` / `@Event` / `@Watch` / `@Element`, functional components). Build
   with `pnpm --filter @univerus/udp-stencil-component-library build`; `docs-readme` regenerates the
   readmes.
4. **React wrappers** in the enterprise library, one per element, the same shape as the chart wrappers
   (`src/UI/powerbi-visuals/UdpPbiColumnChart.tsx`):

   ```tsx
   import React from 'react';
   import { UdpPbiColumnChart as StencilUdpPbiColumnChart, type JSX } from '@univerus/udp-react-stencil-component-library';

   export const UdpPbiColumnChart: React.FC<Partial<JSX.UdpPbiColumnChart>> = (props) => <StencilUdpPbiColumnChart {...props} />;
   ```

   Then `export * from './UdpPbiColumnChart'` in the folder's `index.ts` and in `src/index.ts`. The
   events keep their names (`onDataPointClick`, `onExportData`, `onFocusModeChange`, `onViewChange`).
5. **Theme**: nothing to load. The token bridge falls back to the Fluent tokens the shell already
   injects (light and `body.dark-theme`); `--u-*` is never defined in UDP. Checked against UDP's own
   `src/test/theme/fluent-{light,dark}.css`.
6. **Tests**: the layout math tests (`src/utils/**/*.test.ts`) are plain `describe` / `it` / `expect`
   and run under Stencil's Jest with an import change (`vitest` → globals). The browser checks become
   Playwright `*.e2e.ts` pages like UDP's; stories (`*.stories.ts`) can be written from the PowerReact
   gallery fixtures (`src/components/powerbi-visuals/__fixtures__/samples.ts`).
7. **Dashboards**: each element can be registered as a widget (the Shell `widgets` prop:
   `lazy(() => import(…))` with `layout` and `params`). A manifest visual maps to one widget instance.
8. **Changeset** for `@univerus/udp-stencil-component-library` and the enterprise library (UDP's
   `generate-changeset` skill), plus a `charts/guidance.md` section listing the new elements.

## Not included yet

- **Sankey** (flows between stages): deferred until a report has flow data (source → target → value);
  the waterfall covers the level-to-level bridges the current pages need.
- **Maps**: deferred by decision; they need a basemap and tiling policy agreed with UDP first.

## A documented deviation: `frame="card"`

UDP's standards say "never build what the platform provides" and compose charts inside
`udp-fluent-card`. In `card` mode these elements bring their own card, toolbar menu, focus dialog and
tooltip. Following UDP's *deviating-from-standards* protocol:

- **Standard:** platform components for cards, menus, dialogs and tooltips.
- **Why:** the Univerus visual template (glass card, header, toolbar, hover curtain, focus view,
  Neo-Glass / Nocturne) was approved by Univerus leadership for these reports; rebuilding it from Fluent
  parts would lose that look.
- **Cost:** a second card style next to `udp-fluent-card`; changes to UDP's menus or dialogs do not
  reach these elements automatically.
- **Compliant path:** `frame="none"` renders the visual alone, ready for `udp-fluent-card` and UDP's
  own menus. Its tooltip, keyboard model, selection and events are unchanged.

The owners decide per page; the elements support both.
